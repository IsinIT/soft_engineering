СТАРТ ПРОЕКТА И ВЫБОР МЕТОДОЛОГИИ

**Объем:** 2 академических часа (90 минут)  
**Формат:** Командная работа (3-4 человека в команде)

---

##  ЦЕЛИ ЗАНЯТИЯ

1. Сформировать проектные команды
2. Выбрать идею проекта для семестровой работы
3. Определить методологию разработки
4. Настроить систему управления задачами (Issue Tracker)
5. Создать первичный бэклог продукта в формате User Stories

---

##  ПОЧАСОВОЙ ПЛАН ВЫПОЛНЕНИЯ

### ЧАС 1 (0-45 минут)

#### 0-10 мин: Организационный момент и формирование команд

**Задачи преподавателя:**

- Объявить тему и цели занятия
- Разделить студентов на команды по 3-4 человека
- Распределить роли в командах (можно ротировать позже):
    - **Product Owner** (1 человек) — отвечает за требования
    - **Scrum Master** (1 человек) — фасилитатор процесса
    - **Developers** (1-2 человека) — разработка

**Задачи студентов:**

- Познакомиться с членами команды
- Обменяться контактами (Telegram, email)
- Назначить ответственного за ведение документации

---

#### 10-25 мин: Брейншторминг идей проекта

**Задание:** Каждая команда генерирует 3-5 идей для проекта

**Требования к проекту:**

-  Реализуем за 14 недель (остаток семестра)
-  Веб-приложение или мобильное приложение
-  Backend + Frontend (или мобильный клиент)
-  База данных
-  Аутентификация пользователей
-  Минимум 3 типа пользователей (ролей)
-  Интеграция с внешним API (опционально, но желательно)

**Примеры идей для вдохновения:**

1. **Система управления библиотекой**
    - Пользователи: читатель, библиотекарь, администратор
    - Функции: поиск книг, бронирование, продление, штрафы
2. **Платформа для онлайн-курсов**
    - Пользователи: студент, преподаватель, администратор
    - Функции: просмотр курсов, тесты, сертификаты, прогресс
3. **Система заказа еды в столовой**
    - Пользователи: клиент, повар, менеджер
    - Функции: меню, корзина, заказы, статус приготовления
4. **Трекер привычек (Habit Tracker)**
    - Пользователи: пользователь, друг (социальная функция)
    - Функции: создание привычек, статистика, напоминания, челленджи
5. **Платформа для поиска командных проектов**
    - Пользователи: разработчик, заказчик, модератор
    - Функции: публикация проектов, поиск команды, портфолио

**Алгоритм выбора:**

1. Каждый участник предлагает 1-2 идеи (5 мин)
2. Краткая презентация каждой идеи (2 мин на идею)
3. Голосование или обсуждение преимуществ/рисков
4. Финальный выбор одной идеи

---

#### 25-40 мин: Выбор методологии разработки

**Задание:** Обосновать выбор методологии для вашего проекта

**Чек-лист для принятия решения:**

**Вопросы команде:**

1. Насколько четко вы понимаете требования к проекту?
    - Полностью понятны → Waterfall
    - Частично понятны → Scrum
    - Очень размыты → Kanban
2. Как часто будут меняться требования?
    - Почти не будут → Waterfall
    - Каждые 2-3 недели → Scrum
    - Постоянно и непредсказуемо → Kanban
3. Может ли "клиент" (преподаватель) участвовать постоянно?
    - Только в начале и конце → Waterfall
    - Регулярно (раз в неделю) → Scrum
    - По мере необходимости → Kanban
4. Какой у вас опыт командной работы?
    - Работаем впервые вместе → Scrum (структура поможет)
    - Есть опыт → Любой подход
    - Работаем давно вместе → Kanban (гибкость)

**Рекомендация для учебного проекта:**

> 💡 **Scrum** — оптимальный выбор для 90% учебных проектов, так как:
> 
> - Дает структуру и ритм
> - Позволяет адаптироваться
> - Учит командной работе
> - Соответствует формату курса (итеративная разработка)

**Решение команды:**

- Waterfall
- Scrum (рекомендуется)
- Kanban
- Гибридный подход (Scrumban)

**Обоснование выбора (записать в документацию):**

Мы выбрали методологию [НАЗВАНИЕ], потому что:
1. [Причина 1]
2. [Причина 2]
3. [Причина 3]

Особенности применения в нашем проекте:
- Длина спринта: [1/2/3/4] недели
- Встречи: [описание]
- Артефакты: [список]

#### 40-45 мин: Регистрация в Issue Tracker

**Выбор инструмента (на усмотрение команды):**

**Вариант 1: GitHub Projects (рекомендуется)**

-  Интеграция с репозиторием
-  Бесплатно
-  Простой интерфейс
- [https://github.com/features/project-management/](https://github.com/features/project-management/)

**Вариант 2: Jira (Atlassian)**

-  Профессиональный инструмент
-  Мощная функциональность
-  Сложнее в освоении
-  [https://www.atlassian.com/software/jira](https://www.atlassian.com/software/jira)

**Вариант 3: YouTrack (JetBrains)**

-  Гибкая настройка
-  Бесплатно для небольших команд
-  [https://www.jetbrains.com/youtrack/](https://www.jetbrains.com/youtrack/)

**Вариант 4: Trello**

-  Очень простой
-  Визуальная доска
-  Ограниченная функциональность для разработки
-  [https://trello.com/](https://trello.com/)

###  ЧАС 2 (45-90 минут)

#### 45-65 мин: Настройка Issue Tracker

**Пошаговая инструкция для GitHub Projects:**

**Шаг 1: Создание репозитория**

1. Зайти на github.com
2. Нажать "+" → "New repository"
3. Имя репозитория: [team-name]-[project-name]
   Пример: team-alpha-library-system
4. Visibility: Public (для демонстрации) или Private
5. Initialize with README
6. Add .gitignore (выбрать ваш язык: Python/Java/JS/etc.)
7. Нажать "Create repository"

**Шаг 2: Создание Project Board**

1. В репозитории перейти во вкладку "Projects"
2. Нажать "New project"
3. Выбрать "Board" (Kanban-style)
4. Название: "[Project Name] Board"
5. Нажать "Create"

**Шаг 3: Настройка колонок**

**Для Scrum:**

┌─────────────┬──────────────┬─────────────┬──────────────┐
│   BACKLOG   │ SPRINT READY │ IN PROGRESS │    DONE      │
└───────────────────────────┴─────────────┴──────────────┘

**Для Kanban:**

┌─────────────┬──────────────┬─────────────┬──────────────┐
│   TO DO     │ IN PROGRESS  │   REVIEW    │    DONE      │
│   (WIP: ∞)  │  (WIP: 3)    │ (WIP: 2)    │              │
└─────────────┴──────────────┴─────────────┴──────────────┘

**Шаг 4: Создание Issue Templates**

Создать файл `.github/ISSUE_TEMPLATE/user-story.md`:

markdown

---
name: User Story
about: Описание функциональности с точки зрения пользователя
title: '[USER STORY] '
labels: user-story
assignees: ''
---

## Описание
**Как** [роль пользователя]  
**Я хочу** [выполнить действие]  
**Чтобы** [получить пользу/ценность]

## Критерии приемки (Acceptance Criteria)
- [ ] Критерий 1
- [ ] Критерий 2
- [ ] Критерий 3

## Технические заметки
- [ ] Связанные задачи
- [ ] Зависимости
- [ ] Оценка сложности (Story Points): ?

## Definition of Done
- [ ] Код написан
- [ ] Тесты написаны и проходят
- [ ] Code review выполнен
- [ ] Документация обновлена
- [ ] Функция протестирована на staging

#### 65-85 мин: Создание первичного Product Backlog

**Задание:** Создать минимум 10 User Stories для вашего проекта

**Формат User Story:**

Как [роль пользователя],
Я хочу [выполнить действие],
Чтобы [получить ценность/решить проблему]

**Примеры User Stories для системы библиотеки:**

**US-001: Регистрация пользователя**

Title: [USER STORY] Регистрация нового читателя

Как потенциальный читатель,
Я хочу зарегистрироваться в системе,
Чтобы получить доступ к каталогу книг и возможности бронирования

Acceptance Criteria:
- [ ] Пользователь может ввести email, имя, пароль
- [ ] Система проверяет уникальность email
- [ ] Пароль должен быть минимум 8 символов
- [ ] После регистрации приходит email с подтверждением
- [ ] Пользователь перенаправляется на личный кабинет

Story Points: 3
Priority: High

**US-002: Поиск книг**

Title: [USER STORY] Поиск книг по каталогу

Как читатель,
Я хочу искать книги по названию, автору или ISBN,
Чтобы быстро найти нужную мне литературу

Acceptance Criteria:
- [ ] Поиск по названию (частичное совпадение)
- [ ] Поиск по автору (фамилия, имя)
- [ ] Поиск по ISBN
- [ ] Фильтрация по жанру
- [ ] Сортировка по релевантности/году/рейтингу
- [ ] Отображение статуса availability (в наличии/на руках)

Story Points: 5
Priority: High

**US-003: Бронирование книги**

Title: [USER STORY] Бронирование книги

Как зарегистрированный читатель,
Я хочу забронировать книгу,
Чтобы гарантировать ее получение в библиотеке

Acceptance Criteria:
- [ ] Кнопка "Забронировать" доступна только для книг в наличии
- [ ] Пользователь выбирает дату получения
- [ ] Бронь действительна 3 дня
- [ ] Уведомление на email о подтверждении брони
- [ ] Ограничение: максимум 3 книги одновременно
- [ ] История бронирований в личном кабинете

Story Points: 5
Priority: Medium

**Шаблон для создания User Stories в вашей команде:**

Создайте минимум **10 User Stories**, охватывающих:

1. **Аутентификация и авторизация** (2-3 истории)
    - Регистрация
    - Вход/выход
    - Восстановление пароля
    - Профиль пользователя
2. **Основной функционал** (4-5 историй)
    - CRUD операции для основной сущности
    - Поиск и фильтрация
    - Просмотр деталей
3. **Дополнительный функционал** (2-3 истории)
    - Уведомления
    - Экспорт данных
    - Интеграции
    - Отчеты/статистика

**Приоритизация (MoSCoW метод):**

- **M**ust have — обязательно (без этого продукт не работает)
- **S**hould have — желательно (важно, но можно отложить)
- **C**ould have — возможно (nice to have)
- **W**on't have — не сейчас (в этом спринте/релизе)

#### 85-90 мин: Итоги и домашнее задание

**Проверка готовности:**

Преподаватель проверяет у каждой команды:

- Сформирована команда (3-4 человека)
- Выбрана идея проекта
- Выбрана методология с обоснованием
- Создан репозиторий на GitHub
- Настроен Project Board
- Создано минимум 10 User Stories
- User Stories имеют приоритеты

### Задание 3: Подготовка к Sprint Planning

- Выбрать User Stories для первого спринта (2 недели)
- Общий объем: 13-20 Story Points
- Подготовить ответы на вопросы:
    - Какие задачи самые приоритетные?
    - Какие технические риски вы видите?
    - Что нужно для начала разработки?
